# 数据库设计

## 1. 原则

- 单一 SQLite 数据库 `data/workload.db` 是唯一真实数据源。
- 数量、基准分和工作量以十进制字符串保存，业务计算使用 Python `Decimal`。
- 外键启用，字典记录默认只停用，不物理删除。
- 新建工作记录时保存完整显示快照；以后修改规则或字典不回算旧记录。
- 错误记录使用 `state=VOID` 作废并保留原因和时间。

## 2. 表

| 表 | 用途 | 主要约束 |
|---|---|---|
| schema_meta | 数据库版本 | key 主键 |
| teams | 小组字典 | code、name 唯一；active 软停用 |
| persons | 人员字典 | name 唯一；team_id 外键 |
| projects | 项目字典 | code、name 唯一；active 软停用 |
| quota_rules | 定额规则 | rule_code 唯一；计算方式枚举；active 软停用 |
| work_records | 工作事实与快照 | 日期、人员、项目、规则外键；ACTIVE/VOID 状态 |

## 3. 工作记录快照

除 `person_id`、`team_id`、`project_id`、`rule_id` 外，记录同时保存：

- `person_name_snapshot`、`team_name_snapshot`、`project_name_snapshot`；
- `rule_code_snapshot`、`rule_name_snapshot`；
- `module_snapshot`、`category_snapshot`、`subtype_snapshot`；
- `input_unit_snapshot`、`unit_snapshot`、`base_score_snapshot`；
- `quantity`、`standardized_quantity`、`adjustment_factor_snapshot`、`workload_score`。

因此，把换热器定额从 0.90 修改为 1.00 后，旧记录仍保留 0.90，新记录使用 1.00。

## 4. 索引与可靠性

- 日期、人员+日期、项目+日期、规则+日期、状态+日期均有索引。
- 外键使用 `ON DELETE RESTRICT`，防止历史引用被删除。
- 数据库启用 WAL、10 秒忙等待和 SQLite 在线备份接口。
- 日期和 Decimal 合法性在业务服务层校验。

## 5. 初始化

首次启动创建空工作记录库，并导入：15 名已知人员、4 个小组、8 个项目、29 条规则。现有 Excel 工作记录不导入。
